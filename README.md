# MementoMori 虛寶碼自動領取工具（WPF 版）

WPF 工具，用於批次領取 `https://mememori-game.com/tw/code/` 的虛寶碼。

本工程是 `MementoMoriCodeRedeemer`（WinForms 版）的 WPF 重寫版：**功能完全一致，介面與佈局重新設計**。

## 功能

與原版一致，一項不少：

- 自動讀取官方伺服器列表，並優先沿用上一次選擇的伺服器。
- 選擇伺服器並輸入虛寶碼；可勾選「僅確認不兌換」用於檢查玩家ID、玩家名、世界資訊。
- 本地玩家ID內容庫，支援新增、修改、刪除。
- 玩家可鎖定：鎖定後不可修改、不可刪除。
- 支援搜尋過濾（按玩家ID、備註、最近結果）。
- 支援從剪貼簿批次匯入玩家ID，支援複製整個玩家庫。
- 支援領取勾選玩家或領取全部玩家；批次過程中可取消。
- 每個玩家會先呼叫確認 API，再呼叫傳送 API，間隔 700 ms。
- 逐行顯示最近一次結果，實時進度條（狀態文字在進度條上方、左端與條左端對齊；進度條下邊緣與按鈕下邊緣對齊）與執行日誌（自動裁剪，避免無限增長）。
- 一鍵開啟玩家庫所在目錄。
- 日誌欄旁的隨機立繪：內建 125 張角色立繪（隨 exe 編譯嵌入），每次啟動隨機一張，點選可手動換；資料目錄的 `portraits` 資料夾可擴充輪換池。
- 記住視窗大小：預設以最小尺寸（1120×820）開啟；調整過尺寸或最大化後，下次啟動恢復上次的視窗大小與最大化狀態。

## 玩家庫位置

玩家庫與原版**完全共用**，兩個版本可以交替使用：

```text
%APPDATA%\MementoMoriCodeRedeemer\players.json
```

視窗大小的記錄儲存在同目錄的 `settings.json`（WPF 版新增；刪除該檔案即可讓視窗回到預設大小）。

同目錄下的 `portraits\` 資料夾是立繪擴充套件口：把自己的圖片（`.png`／`.jpg`／`.jpeg`／`.bmp`／`.gif`）放進去，重啟程式就會併入日誌旁立繪的隨機輪換池；目錄為空時只用內建立繪。無法解碼的圖片會被自動跳過，不影響使用。

圖片尺寸不限（大圖在解碼時會等比縮到 192px 寬，記憶體無壓力）；非方圖會**自動取中央正方形**，建議使用 1:1 方圖、邊長 ≥192px、主體儘量居中。各類尺寸的實際顯示效果見 [`docs/portraits-size-demo.png`](docs/portraits-size-demo.png)。

每行剪貼簿匯入格式可以是：

```text
123456789
123456789	備註
123456789,備註
```

## 介面設計說明
原版依賴 GDI+ 逐幀自繪透明控制元件；WPF 版改用宣告式樣式與控制元件模板，把外觀收斂到 `Themes/` 三個字典裡：

- `Palette.xaml`：配色、字型、陰影。水彩／羊皮紙基調（鼠尾草綠 + 陶土 + 金 + 玫瑰）。
- `Icons.xaml`：素材資源鍵。統一使用 `pack://application:,,,/MementoMoriCodeRedeemerWpf;component/Assets/...` 程式集限定寫法。
- `Controls.xaml`：卡片、按鈕、輸入框、下拉框、勾選框、進度條、捲軸、表頭、單元格、行樣式、分隔條。

幾個刻意的取捨：

- **陰影與文字分離**：發光／陰影單獨放在只負責投影的 `Border` 上，正文文字所在層不參與合成，保證 ClearType 不被降級成灰度抗鋸齒。
- **勾選框改為向量繪製**：原版 `ConfirmCheckbox.png` / `ConfirmCheck.png` 是深色遊戲貼圖，放在淺色卡片上會變成難看的黑塊，因此改成向量方框 + 自繪對勾。對勾用 `Path` 且幾何必須從 `(0,0)` 起、並顯式給出 `Width`/`Height`——`Stretch="None"` 時佈局尺寸取的是幾何包圍盒的 `Right`/`Bottom`，幾何起點不在原點就會被整體推向右下，之前那一版就是偏的。對勾墨跡（含筆觸）14.6×10.6，在 20px 方框內四周留白 2.7/4.7，飽滿且居中。
- **設定行存在 1px 溢位陷阱**：視窗壓到最小寬度 1120 時，「虛寶碼」輸入框的彈性列被 `MinWidth=150` 鉗制，整行期望寬超出網格槽位約 1px——排在最後的「僅確認不兌換」勾選框剛好越界，懸停時圓角框的右邊框被裁掉一條（左／上／下都在、唯獨右邊憑空消失）。把該列 `MinWidth` 降到 140 留出餘量後消失。教訓：`*` 列 + `MinWidth` 的組合在視窗壓到下限時會造成 1px 級溢位，被裁的往往是最右元素的描邊，肉眼極難定位。
- **全選圖示不疊第二層框**：工具條的「全選／取消全選」取自遊戲 `toggle_all_on` / `toggle_all_off`，但這兩張原圖自帶一圈水彩外框，而按鈕本身已有圓角底板，直接放上去就是「框套框」。做法是從 67×68 原圖中心取 48×48，再套一個圓形羽化遮罩（`r_out≈23.6 → r_in≈22.0`）把方形四角的外框殘留抹掉，只留裡層球體，顯示尺寸 26px（試過 24/28/30，28 以上會頂到圓角）。素材庫裡的 `icon_sph_all` 也帶環形描邊、`frame_sphere_watercolor` 又太小，都不合適。
- **選中行不再使用貼圖**：原版 `SelectedRowBackground.png` 只有 206×54，橫向 `Stretch="Fill"` 鋪滿整行後，邊緣的水彩筆觸會被拉成一條拖尾，與新版版式不搭，故改為「淡墨綠圓角底 + 左側 3px 筆觸」的純向量方案。
- **行內圖示按鈕沒有懸停效果**：鎖定／勾選狀態由「兩張素材切換」表達，再疊色塊或縮放都屬於多餘干擾，懸停提示只保留手型游標與 ToolTip。整個按鈕區域可點選（模板根節點 `Background="Transparent"`）。
- **進度條與按鈕照遊戲原版貼圖重做**：進度條改為遊戲載入條的樣式——方端、無描邊、半透明灰軌道（與遊戲實拍逐畫素對色），填充沿用 `ProgressFill.png`（左淺右深的綠漸變，色值與遊戲一致，隨填充寬度整體拉伸）；按鈕底圖直接取遊戲 UI 貼圖 `button_l_01` 系列——「領取」的琥珀橙作主按鈕、「取消」的銀白作次按鈕，懸停／按下用提亮／壓暗的烘焙變體切換，不引入執行時特效。之前的圓角膠囊進度條與平面漸變按鈕與遊戲觀感不符，已整段替換。
- **名稱圖示即官方頁面入口**：按原版做法，把可點選的 MementoMori Logo 放在設定區右端（原版 `_logoLink` 是 198×60 的 PictureBox、`SizeMode=Zoom`，實際渲染尺寸 140×60，這裡取同尺寸）。無邊框、無底色、無懸停特效，只保留手型游標與「跳轉至官方頁面」提示。原先獨立成行的品牌標題欄（Logo + 大標題 + 副標題 + 跳轉按鈕）已整塊刪除。
- **同一組數字只出現一處**：玩家總數／已勾選／已鎖定只在列表標題旁的徽章顯示，不在頂部重複。
- **「開啟資料目錄」掛在卡片標題行**：它開啟的是 `players.json` 所在目錄，屬於「玩家ID內容庫」這張卡片的動作，因此和「執行日誌」卡片的「清空日誌」採取同一種位置習慣——卡片標題行右端。搜尋框也在這行，所以按鈕放在搜尋框左側。早先它落在下面工具欄行的最右端，正好吊在搜尋框正下方，看著像搜尋框的附屬按鈕，實際上跟搜尋毫無關係。
  順帶一個坑：`GhostButton` 的底圖是 `Stretch="Fill"` 的水彩貼圖，把它丟進彈性列（`Width="*"`）裡且只給 `MinWidth` 時會被拉成一條長條，必須顯式給出 `Width`。
- **進度條下邊緣與按鈕下邊緣對齊、文字與條左對齊**：操作條一行排完——「領取勾選／領取全部／取消」在左，右側進度塊上方一行是「狀態文字（左）+ 百分比（右）」，進度條沉在下面；**進度條下邊緣與按鈕下邊緣齊**（文字行貼頂），**狀態文字左端與進度條左端對齊**、百分比右端與條右端（卡片右邊距）對齊。進度條始終佔滿進度塊整行寬度，文字長短、數字寬窄都不會推動它；空讀數時兩列收起（`Visibility=Collapsed`），空閒態下進度條單獨貼著按鈕下緣。百分比只給數值、保留一位小數（`77.1%`），不再報「已完成 / 總數」——跑了幾個、還剩幾個看色塊長度和日誌就夠了。任務結束（含取消）後保留最後一次讀數，方便回看這一輪最終跑到哪。
  操作條保持單行，視窗最小高度維持 820：實測 1120×820 時右側編輯欄不會冒出捲軸、「刪除」按鈕也不會被折行。
- **彈窗按鈕不進遊戲貼圖那一套**：主視窗的「領取」用琥珀橙水彩貼圖是合適的，但彈窗裡按鈕是唯一被滑鼠盯著的元素，斑駁的金／銀貼圖壓在乾淨的淺色卡片上太跳；「知道了」只是收個尾，跟「領取」一樣貼金箔也說不過去。故對話方塊的兩個按鈕改用 `PlainButton`——WPF 原生外觀：淺灰底 + 1px 灰邊，懸停／按下走系統那套淡藍高亮（`#E5F1FB` / `#0078D7`）。
- **伺服器下拉框只顯示名稱**：介面用的伺服器編號不對使用者暴露（與原版 `ServerOption.ToString()` 一致）。
- **編輯側欄可滾動**：側欄內容在視窗變矮時不會被裁掉。
- **日誌立繪隨機輪換**：內建 125 張角色立繪取自遊戲圖示庫的 `_m` 規格（256×256），重取樣為 192×192 後隨 exe 編譯嵌入（`EmbeddedResource`，由 `Services/PortraitLibrary.cs` 在執行時列舉資源名），不依賴任何外部檔案。每次啟動隨機一張、點選立繪即再隨機一張（按需求不做去重）；資料目錄 `portraits\` 裡的圖片會併入同一個池子。懸停只保留手型游標與提示，不加其它特效。顯示前有兩步裁剪（都有實測依據）：① 非方圖先取中央正方形——WPF 的 `UniformToFill` 在長寬比不一致時會把溢位部分從右下裁掉（相當於錨定左上角），直接交給它會切偏畫面；② 四角由圖片自身的 `RectangleGeometry` 裁掉——`Border` 即使開了 `ClipToBounds` 也只按矩形裁剪，不裁圓角，否則圖片四角會蓋住圓角邊框。
- **素材全部內嵌**：釋出後仍是單檔案 exe，不依賴外部圖片目錄（125 張立繪一併編譯在內）。

## 與原版的一處有意刪減

原版右下角的 `_statusLabel` 整塊去掉了。它只承擔兩類資訊，而這兩類在別處都有：

| 原狀態列文字 | 現在的去處 |
| --- | --- |
| 正在讀取伺服器列表 / 列表已更新 N 個 / 讀取失敗 | 按鈕禁用態 + 執行日誌 `[伺服器] 已載入 N 個伺服器` |
| 確認 xxx (i/n) / 傳送 xxx (i/n) | 執行日誌 `[確認] xxx`，以及行內「最近結果」列 |
| 完成／已取消：成功 x，跳過 y，失敗 z | 執行日誌 `[完成]` / `[取消]` |
| 進度 5/13 成功 x 跳過 y 失敗 z | 進度條（狀態文字在其上方左對齊，條下邊緣與按鈕對齊）+ 日誌 |

同時刪掉了幾處我自己加的多餘資訊：獨立的品牌標題欄（Logo、大標題、副標題、跳轉按鈕——官方頁面入口已按原版做法並回設定區右端的名稱圖示），以及頂部三個統計方塊（與列表計數徽章重複）。

## 釋出命令

```powershell
dotnet publish .\MementoMoriCodeRedeemer.Wpf.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=None -p:DebugSymbols=false -o .\dist
```

## 執行要求

- 開發：.NET 10 SDK（`net10.0-windows`）。
- 執行：Windows 10 1607 及以上；已宣告 PerMonitorV2 DPI 感知，高 DPI 下不會模糊。
